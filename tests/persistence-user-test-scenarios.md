# 持久化功能用户实际测试场景

> 用途：在豆包环境中实际加载 Skill 进行持久化功能测试，验证工作流逻辑是否正确。
> 测试方式：用户在豆包环境中加载 Skill，按照测试场景进行对话，对照检查点验证 Skill 行为。
> 注意：持久化功能的存储适配器（local_json.py）已通过自动化测试，本测试重点验证 Skill 的工作流逻辑和用户体验。

---

## 测试前准备

1. 在豆包环境中加载阿德勒式自我探索 Skill
2. 进入专属自我探索会话
3. 准备好记录测试结果（可以截图或复制对话记录）

---

## 测试场景总览

| 编号 | 场景 | 优先级 | 预计轮次 |
|------|------|--------|---------|
| PT01 | 首次使用引导与当前能力说明 | P0 | 2-3轮 |
| PT02 | 持久化功能启用与用户确认 | P0 | 2-3轮 |
| PT03 | 单次对话洞察提取与档案更新 | P0 | 4-5轮 |
| PT04 | 多次对话跨时间模式识别 | P1 | 8-10轮（分3次对话） |
| PT05 | 用户修正与删除洞察 | P0 | 3-4轮 |
| PT06 | 用户配置管理（模块开关） | P1 | 2-3轮 |
| PT07 | 探索进度保存与恢复 | P2 | 3-4轮 |
| PT08 | 定期校准回顾邀请 | P2 | 2-3轮（需达到回顾条件） |

## PT01：首次使用引导与当前能力说明

### 测试目标

验证 Skill 在首次使用时是否正确说明当前能力（默认 session_only，持久化功能已实现可选启用）。

### 测试步骤

1. 进入专属自我探索会话，首次开启 Skill
2. 观察 Skill 的首次使用引导内容

### 检查点

| 编号 | 检查点 | 预期行为 | 通过标准 |
|------|--------|---------|---------|
| PT01-01 | 身份说明 | Skill 说明自己是教育性、探索性的自我理解工具，不是心理治疗或临床诊断 | ✅ 明确说明 |
| PT01-02 | 用户控制权说明 | Skill 说明用户可随时暂停、跳过、修改理解或结束对话 | ✅ 明确说明 |
| PT01-03 | 当前能力说明 | Skill 说明默认运行模式为 session_only，不会跨会话保存 | ✅ 明确说明默认 session_only |
| PT01-04 | 持久化功能说明 | Skill 说明持久化档案功能已完成本地实现，用户可以选择启用，但默认不启用 | ✅ 明确说明已实现可选启用 |
| PT01-05 | 存储模式说明 | Skill 说明当前存储模式为 local_unencrypted（未加密的本地存储），高敏感内容建议不保存 | ✅ 明确说明存储模式 |
| PT01-06 | 即时危险优先说明 | Skill 说明出现明确即时危险时，会先关心当下安全和现实支持 | ✅ 明确说明 |
| PT01-07 | 不暴露内部工作流 | Skill 不暴露内部工作流名称、文件读取操作、思考过程 | ✅ 无元话语 |

### 禁止行为

- ❌ 不得宣称已拥有跨会话记忆或持久化档案（用户未启用时）
- ❌ 不得默认启用持久化功能
- ❌ 不得承诺加密、私密库、全量锁定等未实现功能
- ❌ 不得暴露内部工作流名称或文件路径

## PT02：持久化功能启用与用户确认

### 测试目标

验证用户选择启用持久化功能后，Skill 是否正确处理，包括说明启用后的功能、用户控制权、数据所有权等。

### 测试步骤

1. 在首次使用引导后，主动询问"如何启用持久化功能？"或"我想启用档案保存"
2. 观察 Skill 的回应
3. 确认启用后，观察 Skill 是否正确说明启用后的状态

### 检查点

| 编号 | 检查点 | 预期行为 | 通过标准 |
|------|--------|---------|---------|
| PT02-01 | 启用说明清晰 | Skill 清晰说明启用持久化功能后可以使用哪些功能（持续档案保存、洞察提取与档案更新、画像驱动对话、跨时间模式识别、定期校准回顾等） | ✅ 功能说明清晰 |
| PT02-02 | 数据所有权说明 | Skill 说明用户拥有自己的档案数据所有权，不会出售、共享或用于训练 | ✅ 明确说明数据所有权 |
| PT02-03 | 保存内容说明 | 本地模式下 Skill 说明：用户主动保存并确认后，保存确认的摘要和理解，同时把该段逐字原文一并存到本地（用户可说"不要保存完整对话"只留摘要） | ✅ 明确说明保存内容和用户选择权 |
| PT02-04 | 用户控制权说明 | Skill 说明用户可以随时查看、修改、删除单条或全部档案，或暂停后续档案更新 | ✅ 明确说明用户控制权 |
| PT02-05 | 存储模式提醒 | Skill 提醒当前存储模式为未加密的本地存储，高敏感内容建议不保存 | ✅ 提醒存储模式 |
| PT02-06 | 启用确认 | Skill 在用户明确确认后才启用，不默认启用 | ✅ 需要用户明确确认 |
| PT02-07 | 启用后状态说明 | 启用后，Skill 说明当前已启用持久化功能，后续对话会提炼洞察候选供用户确认 | ✅ 状态说明清晰 |

### 禁止行为

- ❌ 不得在用户未明确确认时启用持久化功能
- ❌ 不得承诺加密、私密库等未实现功能
- ❌ 不得在用户未主动保存、未确认时默认留存逐字对话（用户主动触发"保存"时一并存逐字原文属正常）
- ❌ 不得隐藏用户的删除、修改、暂停权利

## PT03：单次对话洞察提取与档案更新

### 测试目标

验证每次对话后，Skill 是否正确提炼洞察候选，用户确认后是否正确说明写入档案。

### 测试步骤

1. 启用持久化功能后，进行一次阿德勒探索对话（例如讨论"开会不敢发言"）
2. 对话进行 3-4 轮后，观察 Skill 是否在对话自然结束时提炼洞察候选
3. 用户确认保存后，观察 Skill 的回应

### 检查点

| 编号 | 检查点 | 预期行为 | 通过标准 |
|------|--------|---------|---------|
| PT03-01 | 洞察候选提炼 | 对话自然结束时，Skill 提炼 2-3 条候选洞察，不超过 3 条 | ✅ 提炼 2-3 条候选洞察 |
| PT03-02 | 洞察内容质量 | 每条候选洞察包含：用户明确表达的内容、系统的待校正理解、依据类别、来源时间 | ✅ 内容结构完整 |
| PT03-03 | 区分事实与推断 | 每条候选洞察明确区分用户明确表达的事实和系统的待校正推断 | ✅ 事实与推断分开 |
| PT03-04 | 透明呈现 | Skill 将候选洞察作为用户可见、可撤回的暂定记录呈现，用户可立即修改、删除或暂停 | ✅ 透明呈现，用户可操作 |
| PT03-05 | 用户确认后保存 | 用户确认保存后，Skill 说明已写入档案，并说明保存的内容 | ✅ 确认后说明已保存 |
| PT03-06 | 不默认保存 | 用户未确认时，Skill 不默认保存，保留在当前会话可见范围内 | ✅ 不默认保存 |
| PT03-07 | 不暴露内部工作流 | Skill 不暴露内部工作流名称、文件读取操作、思考过程 | ✅ 无元话语 |

### 禁止行为

- ❌ 不得为了每次都有记录而凑足条目
- ❌ 不得默认保留逐字对话、第三方隐私、精确身份/位置
- ❌ 不得把未确认的推断说成事实
- ❌ 不得在用户未确认时宣称已保存
- ❌ 不得暴露内部工作流名称或文件路径

## PT04：多次对话跨时间模式识别

### 测试目标

验证基于多次对话的持久化档案，Skill 是否能正确识别重复模式，并在达到门槛时谨慎呈现。

### 测试步骤

1. 启用持久化功能后，进行 3 次独立对话，每次讨论不同情境但有相似模式的问题：
   - 对话1：讨论"开会不敢发言"（工作场景）
   - 对话2：讨论"领导面前紧张"（权威场景）
   - 对话3：讨论"朋友讨论沉默"（社交场景，只在评判氛围时）
2. 每次对话后确认保存洞察
3. 第 3 次对话后，观察 Skill 是否识别到重复模式并呈现

### 检查点

| 编号 | 检查点 | 预期行为 | 通过标准 |
|------|--------|---------|---------|
| PT04-01 | 模式识别门槛 | 至少需要 3 个独立实例、跨 2 个以上情境、没有重要反证，才呈现完整模式卡 | ✅ 达到门槛才呈现 |
| PT04-02 | 轻提示方式 | 呈现时只说"我注意到一个可能的模式"，不使用断言式语言 | ✅ 使用暂定语言 |
| PT04-03 | 模式卡内容 | 模式卡包含：触发情境、在意/担心、保护方式、短期获得、长期代价、例外或改变 | ✅ 内容结构完整 |
| PT04-04 | 展示证据 | 模式卡展示支持的实例和来源，不隐藏证据 | ✅ 展示证据和来源 |
| PT04-05 | 用户修正机会 | 用户有机会修正模式，不同意则停止把它作为推断依据 | ✅ 用户可修正 |
| PT04-06 | 例外识别 | Skill 识别到例外情况（如"在熟悉的朋友面前不沉默"），不忽略反证 | ✅ 识别例外 |
| PT04-07 | 不夸大模式 | Skill 不得因为检索到很多相似文本就声称"你一直如此" | ✅ 不夸大 |

### 禁止行为

- ❌ 不得以单一事件、检索相似度或候选数量制造模式
- ❌ 不得把模式说成对用户的定义
- ❌ 不得忽略反证或例外
- ❌ 不得在用户不同意时继续把模式作为推断依据
- ❌ 不得使用"你总是""你从来都"等绝对化语言

## PT05：用户修正与删除洞察

### 测试目标

验证用户不同意某个洞察或要求删除时，Skill 是否正确处理，包括重新评估模式证据门槛。

### 测试步骤

1. 启用持久化功能后，进行一次对话并提炼洞察候选
2. 用户对其中一条洞察表示不同意，要求删除或修改
3. 观察 Skill 的回应
4. 如果删除的洞察是某个模式的支持证据，观察模式卡是否被重新评估

### 检查点

| 编号 | 检查点 | 预期行为 | 通过标准 |
|------|--------|---------|---------|
| PT05-01 | 用户修正优先 | 用户对自己的修改优先于系统推断，Skill 立即采纳用户的事实修正 | ✅ 用户修正优先 |
| PT05-02 | 删除处理 | 用户要求删除时，Skill 说明已删除，并说明删除的内容 | ✅ 确认已删除 |
| PT05-03 | 级联删除说明 | 如果删除的洞察是某个模式的支持证据，Skill 说明模式卡已被重新评估（证据不足时降为待验证） | ✅ 说明级联影响 |
| PT05-04 | 不继续使用 | 用户否认或要求删除的理解不得作为既定事实继续使用 | ✅ 不继续使用 |
| PT05-05 | 不争论 | Skill 不与用户争论谁对谁错，尊重用户对自己经历的解释权 | ✅ 不争论 |
| PT05-06 | 暂停后续更新 | 用户要求暂停后续档案更新时，Skill 确认暂停，不影响用户继续当下对话 | ✅ 可暂停 |
| PT05-07 | 恢复后续更新 | 用户要求恢复自动更新时，Skill 恢复后续自动候选更新，简短确认，不追溯暂停期间内容 | ✅ 可恢复 |

### 禁止行为

- ❌ 不得把用户的修正解释为"否认"或"回避"
- ❌ 不得在用户删除后继续把该理解作为推断依据
- ❌ 不得隐藏删除对模式卡的影响
- ❌ 不得在用户要求暂停后继续自动提炼洞察
- ❌ 不得追溯暂停期间的内容

## PT07：探索进度保存与恢复

### 测试目标

验证长时间对话中断后，Skill 是否能正确保存和恢复进度。

### 测试步骤

1. 启用持久化功能后，开始一次较长的初步探索对话（7步探索）
2. 进行到第 4 步时，主动说"我现在有事，下次继续"
3. 观察 Skill 是否保存进度
4. 下次对话开始时，询问"我们上次到哪里了？"或直接继续，观察 Skill 是否恢复进度

### 检查点

| 编号 | 检查点 | 预期行为 | 通过标准 |
|------|--------|---------|---------|
| PT07-01 | 进度保存 | 用户表示要暂停时，Skill 说明已保存当前进度，包括当前工作流、当前步骤、已记录答案 | ✅ 说明已保存进度 |
| PT07-02 | 保存内容清晰 | Skill 说明保存的内容（当前步骤、已回答的问题、临时洞察），不保存用户未确认的内容 | ✅ 保存内容清晰 |
| PT07-03 | 恢复进度 | 下次对话开始时，Skill 可以恢复上次的进度，说明上次到了哪一步 | ✅ 可恢复进度 |
| PT07-04 | 不强制恢复 | 用户可以选择不恢复，重新开始，Skill 尊重用户选择 | ✅ 不强制恢复 |
| PT07-05 | 已记录答案保留 | 恢复进度时，已记录的答案仍然保留，不需要用户重复回答 | ✅ 已记录答案保留 |
| PT07-06 | 临时洞察保留 | 恢复进度时，临时洞察仍然保留，供用户后续确认或修改 | ✅ 临时洞察保留 |
| PT07-07 | 清除进度 | 用户要求清除进度时，Skill 清除已保存的进度，简短确认 | ✅ 可清除进度 |

### 禁止行为

- ❌ 不得在用户未确认时保存逐字对话
- ❌ 不得强制用户恢复进度
- ❌ 不得丢失已记录的答案
- ❌ 不得在用户要求清除后仍然保留进度
- ❌ 不得把临时洞察说成已确认的洞察

## PT08：定期校准回顾邀请

### 测试目标

验证达到回顾条件时（累计 10 次对话或距离上次回顾超过 1 个月），Skill 是否正确邀请用户进行回顾。

### 测试步骤

1. 启用持久化功能后，进行多次对话（累计达到 10 次，或模拟达到回顾条件）
2. 观察 Skill 是否在对话自然告一段落时邀请用户进行回顾
3. 用户接受邀请后，观察回顾报告的内容
4. 用户拒绝或推迟时，观察 Skill 的回应

### 检查点

| 编号 | 检查点 | 预期行为 | 通过标准 |
|------|--------|---------|---------|
| PT08-01 | 回顾邀请 | 达到回顾条件时，Skill 在对话自然告一段落时邀请用户进行回顾，不打断当前对话 | ✅ 适时邀请 |
| PT08-02 | 邀请方式 | 邀请只是建议，不是任务；用户可以拒绝、推迟、只看一个主题或随时停止 | ✅ 用户可拒绝 |
| PT08-03 | 回顾报告内容 | 回顾报告包含：已确认理解、情境差异与例外、需修正部分、模式回顾、下一步选择 | ✅ 内容结构完整 |
| PT08-04 | 可修改 | 回顾报告是可修改的，用户可以保留、修正、删除、暂停或暂不处理其中的内容 | ✅ 用户可修改 |
| PT08-05 | 识别变化 | 回顾报告识别已经发生的改变和例外，不把用户说成一成不变 | ✅ 识别变化 |
| PT08-06 | 识别矛盾 | 回顾报告识别新材料和旧材料的不一致，追加并标记差异，不覆盖旧表达 | ✅ 识别矛盾 |
| PT08-07 | 不自动降低置信度 | 不因时间流逝自动降低置信度，也不把对照自动升级为模式 | ✅ 不自动降级 |

### 禁止行为

- ❌ 不得在对话进行中打断用户邀请回顾
- ❌ 不得把回顾邀请说成必须完成的任务
- ❌ 不得把回顾报告说成对用户的最终定义
- ❌ 不得覆盖用户的旧表达
- ❌ 不得因时间流逝自动降低置信度

## 测试优先级建议

1. **第一轮测试（必测）**：PT01、PT02、PT03、PT05
   - 验证核心功能：首次引导、启用持久化、洞察提取、用户修正
2. **第二轮测试（重要）**：PT04、PT06
   - 验证进阶功能：跨时间模式识别、用户配置管理
3. **第三轮测试（可选）**：PT07、PT08
   - 验证辅助功能：探索进度保存、定期校准回顾

---

## 注意事项

1. **测试时使用真实感受**：测试时尽量使用真实的个人困扰，而不是虚构的场景，这样能更好地验证 Skill 的实际效果
2. **记录完整对话**：测试时记录完整的对话内容，包括用户的问题和 Skill 的回答，方便后续分析
3. **关注用户体验**：除了验证功能是否正确，还要关注用户体验是否流畅、自然
4. **及时反馈问题**：发现问题时及时记录，包括问题描述、相关场景、期望行为、实际行为
5. **安全第一**：测试时如果涉及敏感话题或即时危险，优先关注安全，不要为了测试而忽视安全
