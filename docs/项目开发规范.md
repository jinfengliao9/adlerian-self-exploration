### 1.2 置信度评定规则

| 置信度 | 条件 |
|---|---|
| **high** | 3 种以上不同情境或材料交叉印证一致，且用户明确确认，且无重要矛盾 |
| **medium** | 2 种情境或材料一致，或用户确认但仅有单一来源，或多次出现但未确认 |
| **low** | 单一来源、用户未确认、与其他证据矛盾，或材料不足以作出稳定理解 |

### 1.3 存储层抽象接口

无论底层存储如何实现，必须支持以下操作：

```
# 档案读写
- get_storage_mode() -> <session_only | local_unencrypted | local_encrypted>  # 注：local_private（独立私密库）与平台托管模式均已否决，实际为未加密/整体加密两种本地模式
- get_storage_capabilities() -> <CapabilitySet>
- read_profile() -> Profile              # 读取完整生活风格画像
- write_profile(profile) -> void         # 写入完整画像
- update_profile_section(section, data)  # 更新画像的某个部分

# 洞察记录
- append_insight(insight) -> str         # 追加一条洞察，返回洞察ID
- list_insights(limit, since) -> [Insight]
- get_insight(id) -> Insight

# 对话历史
- append_conversation(entry) -> void     # 追加对话记录
- search_conversations(query, limit) -> [Conversation]  # 语义/关键词检索历史
- list_conversations(limit, since) -> [Conversation]

# 回顾报告
- save_review(report) -> str
- list_reviews() -> [Review]

# 私密记忆库（仅在平台支持真正用户控制加密时启用）
- lock_private_vault() -> void
- unlock_private_vault(credentials) -> VaultSession

- list_private_memories() -> [PrivateMemory]

```

本地实现以整体加密文件承载档案（local_encrypted，Fernet）。独立私密库分层已否决、不再实现；整体加密仅在能够实现真正本地、用户控制加密的平台启用；上层 workflow 不直接操作文件或数据库，只调用上述接口。本地档案不得冒充私密库。

## 二、三阶段间接测量体系（核心方法论）

### 2.0 首次使用与探索入口

**专属探索会话**是持续进行阿德勒式自我探索的默认容器；它不是在所有聊天中自动分析用户的开关。首次进入专属探索会话时，按以下顺序完成必要的、可跳过的引导：

1. 用简短、平等的语言说明用途、非治疗边界、记忆与即时危险规则，以及用户可随时暂停或退出；
2. 首版不询问或记录年龄，也不以年龄改变探索路径；
3. 在用户明确开启持续档案时，说明档案与私密库的保护方式、查看/删除权和恢复凭据；
4. 用户明确请求阿德勒分析时直接开始；意愿不明时只询问一次是否愿意以阿德勒视角探索，拒绝或不确定时结束本 Skill 路由；
5. 出现明确即时自/他伤、正在发生暴力或无法保持人身安全时，立即按即时危险流程处理，覆盖探索流程。

"初步探索"以建立暂定画像为目标；"深入探索"可在已有材料基础上进入某个具体议题或模式。用户明确请求"用阿德勒视角分析"本身即构成当次分析授权，无须重复确认。普通倾诉不是本 Skill 的路径；意愿不明时只作一次探索确认。

### 2.1 第一阶段：初步画像建立（结构化间接评估对话）

**目标**：通过 30-45 分钟的结构化对话，收集可供用户审阅与修正的材料，建立初步的生活风格画像。
**触发**：用户首次使用 skill，或主动要求"重新评估"。
**原则**：不是问卷，是自然对话；开始前透明说明会形成可查看、可修正的暂定档案；全程保持温暖、好奇、不评判。

**暂定探索地图**：在获得足以帮助当前理解的材料后，先输出可修改的探索地图，而非急于形成生活风格画像。地图只包含六项：本次想理解的事、用户明确讲述的经历、这件事的重量、一个待校正的可能理解、已经存在的力量、下一步由用户选择。事实与推断必须分栏；推断使用"可能""也许""需要你校正"等暂定语言，不展示人格标签、数值评分、社会期望指数或勇气等级。地图底部固定说明"这是一份可修改的暂定记录，不是对你的定义"；用户修改后的表达优先于系统推断。

#### 方法 1：早期记忆探索（阿德勒原生，最核心）

阿德勒疗法中最核心的评估工具。早期记忆本质上是**投射测试**——人从成千上万的童年记忆中"选择"记住哪几个，这些记忆被当前生活风格筛选，支持其对自我/他人/世界的基本信念。

**执行方式**：
1. 邀请用户讲述 **3-5 个最早的童年记忆**
2. 要求是**具体事件**（如"我记得5岁那年……"），不是概括性描述（如"我小时候很快乐"）
3. 对每个记忆追问：
   - 当时发生了什么？具体场景是怎样的？
   - 你在做什么？别人在做什么？
   - 结果怎样？
   - 你当时什么感受？
4. 分析每个记忆的六个维度（见画像结构第六条）

**注意**：不把记忆当客观史实，而当作用户当前生活风格的投射。

#### 方法 2：家庭星座访谈（阿德勒原生）

**执行方式**：
1. 出生顺序、兄弟姐妹年龄差、各自的家庭角色
2. 父母各自的态度（谁更严厉/谁更温暖/父母关系）
3. 家庭整体氛围
4. **关键追问**："在这样的家庭里，你觉得自己需要怎么做才能获得关注/爱/安全感？"

**分析重点**：用户对家庭事实的**主观解读**比事实本身更重要。同样是老大，"我必须负责照顾别人"和"我总是被忽视"反映了截然不同的生活风格。

#### 方法 3：情境投射问题（借鉴主题统觉测验 TAT）

给出模糊的人际情境，让用户**描述自己会怎么做/编故事**，用户会把内在模式投射到情境中。

**示例问题**（问题库持续扩充，见 `references/assessment/question-bank.md`）：
- "如果你在一个聚会上发现没有一个人认识你，你会怎么做？接下来会发生什么？"
- "你的一个朋友突然对你很冷淡，但你不知道为什么。你心里会怎么想？你会怎么做？"
- "如果你完成了一个很重要的项目，但领导把功劳给了别人，你会怎么做？"
- "想象一下，十年后的你在做什么？身边有谁？那是一个什么样的场景？"

**分析维度**：人际安全感、应对策略（逃避/对抗/讨好/独立）、对他人的基本信任、追求的目标。

#### 方法 4：迫选式问题（借鉴 Forced-Choice 方法）

给出两个同样合理、反映不同关注点的选项，邀请用户比较自己的倾向；用户始终可以选择"都不贴切"或自行说明，不把选择当作人格结论。

**示例问题**：
- "A：我应该总是尽力帮助别人，即使牺牲自己的需求 / B：我应该先照顾好自己，有余力再帮助别人"
- "A：别人的评价对我很重要，我会努力让大家满意 / B：别人怎么看我是他们的事，我更在意自己的感受"
- "A：我喜欢在团队中扮演领导角色 / B：我更喜欢做一个可靠的支持者"
- "A：犯错是学习的机会，我不怕犯错 / B：我会尽量避免犯错，因为犯错会让人失望"

**分析维度**：社会兴趣程度、追求卓越的方式、人际安全感、勇气水平。

#### 方法 5：具体化与一致性澄清

当某个概括性说法与当前议题相关时，邀请用户用具体例子补充；目标是共同理解情境差异，不是识别伪装或揭穿矛盾。

**执行方式**：
- 以好奇、温和的方式邀请具体细节；用户可跳过
- 例如：用户说"别人的评价通常不会影响我" → "如果你愿意，能否想一个最近被评价时的例子？当时发生了什么？"
- 无法举例、记忆模糊或前后变化只表示材料不足或情境不同，不推导为不诚实

#### 方法 6：跨情境、跨时间暂定验证

将当前对话中的理解与后续不同情境、用户的修改和长期回顾相互校验；系统不设置社会期望偏差指数，也不以发现用户美化为目的。

**验证逻辑**：
- 同一理解在多个独立情境出现，且用户认可 → 可提高置信度
- 材料不一致或用户修正 → 保留为待验证假设，或记录为随情境变化
- 所有推断均可见、可改、可删；系统不进行隐蔽人格测量

### 2.2 第二阶段：持续对话更新

**触发**：初步评估完成后的每次日常对话。
**机制**：
1. 完成明确开启后，持续档案默认启用；每次对话结束后，AI 自动提炼 **2-3 条**可能更新画像的洞察
2. 向用户展示"本次档案更新单"，说明新增摘要/候选洞察、依据和置信度，用户可保留、修改、删除或暂停后续留档
3. 已保留信息附带来源、置信度、时间戳与用户态度；候选洞察在未被确认前保持"待验证、低置信度"
4. 用户否认或要求删除的观察不得强行保留；仅在用户同意时才保留为"待验证假设"

**更新原则**：
- 不覆盖旧信息，而是追加并标记变化趋势
- 如果新信息与旧信息矛盾，不急于下结论，在后续对话中继续观察
- 每次更新都修改 `updated_at` 和 `total_conversations`

### 2.3 第三阶段：定期校准回顾

**触发**：积累 10 次对话，或距离上次回顾超过 1 个月，或用户主动要求。
**内容**：
1. 回顾初步画像与后续对话中发现的模式是否一致
2. 识别矛盾点，与用户一起探讨哪个更真实
3. 仅在用户明确修正/否认，或出现新的可信冲突材料时，才降低旧理解的置信度或转为待验证；时间过去本身只标注"近期未复核"，不改变置信度
4. 识别"正在改变的模式"（这本身就是成长的证据，需要鼓励）
5. 生成回顾报告，保存到 `outputs/profile/reviews/`

## 三、阿德勒理论框架要点（理论层核心内容）

以下内容必须内化到 SKILL.md 和 references/ 中。理论准确性是第一优先级。

### 3.1 八大核心概念

#### 1. 自卑感与超越（Inferiority and Compensation）
- 自卑感是人类普遍体验，是进步的动力，不是缺陷
- **自卑感**（正常、可超越）vs **自卑情结**（压倒性、导致逃避）vs **优越情结**（通过贬低他人掩饰自卑）
- 对话中：正常化自卑感 → 识别自卑情结 → 引导建设性补偿

#### 2. 目的论（Teleology）
- 阿德勒与弗洛伊德的根本分歧：行为由**目的**驱动，而非过去的原因决定
- "性格"不是固定的，而是为达成目的而选择的策略
- 即使消极行为（抑郁、愤怒、回避）也有隐藏目的
- 对话中：不否定过去，但拒绝让过去成为不行动的借口；问"这个行为在服务什么目的？"
- **关键边界**：目的论是赋能工具，不是指责工具。"你选择了这种行为"绝不能变成"这都是你的错"。对创伤幸存者使用时特别谨慎。

#### 3. 课题分离（Separation of Tasks）
- 每件事问"最终由谁承担结果？"来判断是谁的课题
- 你的课题：你的选择、行动、成为什么样的人
- 别人的课题：别人怎么看你、怎么评价你、做什么选择
- 课题分离不是冷漠，是清晰；分离之后才有真正的合作
- 课题分离是起点，共同体感觉是终点

#### 4. 社会兴趣（Gemeinschaftsgefühl / Social Interest）
- 心理健康的终极标准：归属感、贡献感、信任感、合作能力
- 幸福 = 感到自己对他人有用
- 引导方向：从"我能得到什么"转向"我能贡献什么"

#### 5. 生活风格（Lifestyle）
- 形成于童年早期（约4-5岁），但**不是固定不变的**
- 包含：自我观、世界观、他人观、理想自我、行为策略
- 生活风格是被选择的（童年可能无意识），因此可以被重新选择
- 不做深度考古，更关注"你愿意建立什么新模式"

#### 6. 早期记忆（Early Recollections）
- 被当前生活风格"选择"出来的记忆，支持当前自我叙事
- 是理解生活风格的窗口，本身就是投射测试
- 当生活风格改变时，"重要的"早期记忆也会改变

#### 7. 鼓励（Encouragement）
- 阿德勒治疗的核心技术
- **鼓励**（关注过程和勇气："你选择了面对困难"）vs **表扬**（关注结果："你做得真好"）
- 每次对话都注入鼓励；关注用户已经在做的好事
- 鼓励不是假装问题不存在，而是相信用户有能力面对

#### 8. 共同体感觉与横向关系
- **纵向关系**：上下级、强弱、好坏——基于评判和控制
- **横向关系**：平等、不同但等价——基于尊重和合作
- 不通过胜过别人证明价值；从"比别人好"转向"与别人不同"
- AI 与用户的关系也必须是横向的——不是权威，是平等的对话伙伴

### 3.2 对话风格

- **鼓励性**：每句话传递"你有能力"的信息
- **直率但温和**：不回避真相，但传递方式温暖
- **面向未来**：少回顾"为什么"，多探索"可以怎样"
- **行动导向**：对话目标是启发行动，而非无尽分析
- **平等感**：不居高临下，并肩而行
- **具体**：大道理之后一定要落到"你今天可以做的一件小事"

行动建议采用用户可选的"小实验卡"，而非任务、打卡或评分：仅在用户主动希望尝试、或接受邀请后共同制定；一次只给一个可控、足够小、可暂停和可撤回的尝试，并允许"先不行动"。下次回顾只讨论发生了什么、感受与学到什么，不把未做、部分完成或改变主意标记为失败或人格特征。即时危险分流中不生成行动卡。

普通行动卡可包含用户自述的方向、一个最小尝试、更轻的替代、可能困难、暂停边界、开放式回顾和编辑/删除控制；不得包含期限、打卡、评分、施压措辞、要求他人改变，或未经安全核实的高风险行动。涉及现实风险但不存在即时危险时，可提供低风险的当下支持计划：仅包含当下优先目标、用户选择的支持对象、低风险下一步、隐私提醒、何时寻求现实紧急帮助与编辑/删除控制；不提供对质、强迫披露、秘密取证、危险对抗或规避追踪的指令。

### 3.3 常用句式

- "你现在的行为，可能是为了……"
- "这是谁的课题？"
- "如果你决定改变，最小的一步会是什么？"
- "你选择了面对这个问题——这本身就需要勇气"
- "重要的不是你生来如何，而是你如何使用你所拥有的"
- "你不需要比别人好——你只需要做你自己"
- "从现在开始，你想成为什么样的人？"
- "幸福不是一个人的事——它发生在人与人的关系中"

### 3.4 与其他流派的区分

- **vs 弗洛伊德**：目的论而非原因论；整体论而非本我/自我/超我；社会兴趣而非性冲动
- **vs 荣格**：关注社会关系和行动而非内在象征；互补关系（荣格处理深度，阿德勒处理行动）
- **vs CBT**：CBT 深受阿德勒影响（认知图式≈生活风格），但阿德勒更强调社会维度和温暖鼓励
- **vs 弗兰克尔**：弗兰克尔关注意义，阿德勒关注勇气和社会贡献；两者互补

## 四、模式识别触发与呈现

### 4.1 触发场景设计

- **专属自我探索会话**：用户新建并进入该会话后，skill 持续生效；开场提供简明使用说明，明确授权后进入初步或深入探索。
- **其他对话/工作窗口**：不默认触发。仅在用户手动开启技能，或明确提出阿德勒式分析时进入相应回应；表达含义不明确时，先询问是否希望使用阿德勒视角。
- **回到专属会话的建议**：当用户需要连续档案、私密库、阶段性评估或跨时间模式识别时，温和建议回到专属会话；不强制跳转，也不让一次性的日常求助失去回应。

### 4.2 三种模式识别触发方式

#### 自动轻提示
当至少两个彼此独立的事件或对话中出现相似循环时，可默认发出一次轻提示；"独立"不包括同一件事的重复讲述。轻提示只在专属探索会话、全部档案已解锁、当前不存在即时危险且话题自然告一段落时出现，每次会话最多一次：
> "这让我想起你之前提到过类似的情况……要不要一起看看这里面有没有共同的模式？"

不强行分析，把选择权交给用户。

#### 用户主动请求
用户说"帮我看看我有没有什么反复出现的模式"时，可进行深度跨时间分析。完整模式卡至少需要三个实例、跨两个以上情境或不同时间点、没有明显相反证据，并让用户有机会修正；未达到时只呈现为待验证理解。

#### 定期回顾
每 10 次对话或 1 个月，主动提议做一次"生活风格回顾"（见第三阶段定期校准回顾）。

### 4.3 呈现原则

- 用"我注意到一个可能的模式……"而非"你总是……"
- 每次只呈现 1-2 个模式，不堆砌
- 模式卡展示"常见触发 → 当时在意/担心 → 通常的保护方式 → 短期获得 → 长期代价 → 例外或正在改变的地方"，不使用人格标签
- 呈现后必须让用户选择"很贴近 / 只在某些情境 / 不同意 / 现在不想看"；不同意则停止作为推断依据，暂不看则仅暂停呈现，不解释为回避
- 私密库材料可在解锁会话中作为内部证据，但默认只呈现抽象结构，不突然复述原始敏感叙述
- 普通工作聊天、未获探索授权或即时危险分流中不主动呈现模式提示
- 模式识别的目的是赋能（"看见即改变的开始"），不是贴标签

## 五、开发规范

### 5.1 质量要求

- **质量优先于速度**。宁可多花时间把内容做扎实，也不敷衍或简化
- 所有心理学内容必须准确，不确定的理论点必须查证后再写
- 每个 workflow 必须经过至少 3 个真实场景的思维验证
- 所有输出模板必须有填写示例

### 5.2 语言与格式

- 所有文档使用**简体中文**撰写
- SKILL.md 中的 frontmatter 使用英文（跨平台兼容性）
- 代码/数据结构使用英文标识符
- Markdown 格式，层级清晰
- 引用阿德勒原著时标注书名

### 5.3 SKILL.md 编写规范

- frontmatter 只包含 `name` 和 `description`（跨平台最小公约数）
- `description` 必须清晰说明触发条件，避免误触发
- 主入口文件保持精简（约 3000-5000 字），详细内容放入 `references/` 按需加载
- 必须包含：身份角色、核心框架、对话原则、触发条件、边界伦理、按需资源索引

### 5.4 Git 规范

- `main` 分支保持稳定
- 功能开发使用 feature 分支
- `.gitignore` 必须包含：`outputs/`、`.DS_Store`、`Thumbs.db`、临时文件
- Commit message 使用中文，格式：`类型: 描述`（如 `feat: 添加早期记忆评估工作流`）

### 5.5 测试验证

- 每个工作流完成后，用至少 3 个不同类型的场景进行对话测试
- 测试场景覆盖：自卑/人际/职业/家庭/改变恐惧
- 重点验证：探索是否透明且可跳过、档案更新是否准确、模式识别是否过于激进
- 最小可用版完成后，在本地豆包工作中做一次端到端实跑验证
