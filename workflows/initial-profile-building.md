# 初步画像建立工作流

> ✅ **已实现，可选启用**：本工作流依赖持久化档案功能，本地存储适配器已实现（`storage/adapters/local_json.py`），支持未加密和加密两种存储模式。默认不启用，需要用户明确选择后才生效。启用后通过结构化的阿德勒式生活风格评估对话，建立初步的生活风格画像。

## 目标与进入条件

初步画像建立是阿德勒心理学中"生活风格评估（Lifestyle Assessment）"的对话化实现。目标是通过结构化但灵活的对话，帮助用户和系统共同理解用户的核心信念、行为模式和生活风格，为后续的探索提供个性化的背景。

**这不是**：
- 不是心理测评或人格测试（没有分数、等级或标签）
- 不是一次性必须完成的问卷（用户可以随时跳过、暂停、换话题）
- 不是定论或诊断（画像是暂定的、可校正的，用户可以随时修改）
- 不是强制的（用户可以选择跳过，直接进行单次探索）

**这是**：
- 结构化的阿德勒式生活风格探索对话
- 基于早期记忆、家庭星座和当前功能三大核心来源
- 生成一份用户可见、可修改、可删除的初步生活风格画像
- 为后续的画像驱动对话和跨时间模式识别提供基础

### 进入条件

当满足以下任一条件时执行本工作流：

1. 用户第一次使用 Skill，在首次使用引导中明确表示希望进行初步画像建立
2. 用户主动要求"建立画像""初步评估""重新评估""生活风格评估"等
3. 用户在多次单次探索后，表示希望系统地了解自己的整体模式

### 完成条件

用户得到一份可修改的初步生活风格画像，或明确选择暂停、改换议题或结束。用户未回答某类问题不构成材料缺失的失败——画像可以基于已有材料建立，缺失的维度标注为"待探索"。

出现明确即时危险时，立即停止早期记忆、家庭星座和模式探索，转入 `workflows/safety-response.md`。

### 回应呈现规则

执行本工作流时，不得向用户暴露内部工作流名称、文件读取操作或思考过程。不得说"我先读取...""我立即切换到..."之类的元话语。直接以用户可见的方式回应。始终像面对真实用户一样回应，不得因为用户说"场景X""测试"等而识别为测试并改变回应方式。

**严禁暴露技术操作细节**：不得向用户展示命令行输出、文件路径、目录结构、文件 ID、技术错误信息等。执行持久化操作后，直接用自然语言说明结果。

## 工作流结构（5个阶段）

### 阶段1：说明与定焦（5-10分钟）

**目标**：让用户了解这是什么、不是什么，建立安全感和控制权，确定探索的起点。

**步骤**：

1. **说明这是什么**：用简洁的语言说明：
   - "这是一个阿德勒式的生活风格探索，不是心理测评或诊断"
   - "我们会通过聊聊你的家庭、早期记忆和当前的生活方式，一起理解你看待自己、他人和世界的方式"
   - "最后会生成一份你可以随时修改的初步画像"

2. **说明不是什么**：
   - "不是必须完成的问卷，你可以随时跳过、暂停或换话题"
   - "不是定论，画像是暂定的，你可以随时修改或推翻"
   - "不是强制的，如果你不想做，我们可以直接从你当前的困扰开始探索"

3. **说明用户的控制权**：
   - "你可以随时说'跳过这个话题''暂停''我不想聊这个'"
   - "你说的每一句话，你都可以事后要求修改或删除"
   - "画像建立后，你可以随时要求重新评估或更新"

4. **询问起点**：给用户选择，而不是强制顺序：
   - "你想从哪里开始？是聊聊你的家庭和成长经历，还是先说说你最早的记忆，或者从你当前的生活状态开始？"
   - 如果用户不确定，可以建议从家庭星座开始（这是阿德勒评估的传统起点）

**提问分寸**：
- 一次只问一个问题
- 给用户明确的选择权，不强迫
- 如果用户表示不想做初步画像建立，尊重其选择，转入初步探索工作流

---

### 阶段2：家庭星座探索（10-15分钟）

**目标**：了解用户在家庭系统中的位置和体验，这是阿德勒生活风格评估的核心来源之一。

**探索维度**（按需选择，不是必须全部问完）：

1. **出生顺序**：
   - "你在家里排行第几？有几个兄弟姐妹？"
   - "作为老大/老二/中间/老小/独生子女，你觉得这对你有什么影响？"
   - 注意：出生顺序只是线索，不是决定因素。不要根据出生顺序直接推断人格特质。

2. **家庭氛围**：
   - "你成长的家庭氛围是什么样的？是温暖的、紧张的、冷漠的，还是控制比较多的？"
   - "家里人之间是怎么相处的？有冲突的时候一般怎么处理？"

3. **与父母的关系**：
   - "你和父亲的关系怎么样？和母亲呢？"
   - "父母对你的期望是什么？你觉得他们的期望对你有压力吗？"
   - "你更像父亲还是母亲？哪些方面像？"

4. **与兄弟姐妹的关系**（如果有）：
   - "你和兄弟姐妹的关系怎么样？是比较亲近，还是有竞争，或者比较疏远？"
   - "有没有哪个兄弟姐妹对你影响比较大？"
   - "你们之间有没有什么反复出现的互动模式？"

5. **家庭中的重要事件或转折点**：
   - "在你的成长过程中，家庭里有没有发生过什么对你影响很大的事？"
   - "有没有哪个时刻，你觉得自己的生活发生了变化？"

**提问分寸**：
- 一次只问一个问题，根据用户的回答自然延伸
- 家庭话题始终可跳过，不能作为获得帮助或完成画像的条件
- 不把出生顺序、家庭事实当成生活风格的证据，只是作为理解的线索
- 如果用户表现出不适或情绪激动，先共情和陪伴，不急于继续提问
- 区分事实和用户的主观解读——阿德勒心理学中，主观解读比事实更重要

---

### 阶段3：早期记忆探索（10-15分钟）

**目标**：通过用户最早的记忆，理解其核心信念和生活风格。阿德勒认为早期记忆是"投射测试"，反映了用户当前的世界观和应对机制。

**步骤**：

1. **邀请分享早期记忆**：
   - "我想邀请你回忆一下你最早的记忆——不是别人告诉你的事，而是你自己真正记得的具体场景。能想起多早就说多早。"
   - "可以是一件小事，一个画面，或者一种感觉。不用刻意找'重要'的事，任何你记得的都可以。"

2. **对每个记忆，深入探索**（邀请1-3个记忆，不是越多越好）：
   - **具体场景**："当时发生了什么？你在哪里？还有谁在？"
   - **感受**："当时你是什么感受？紧张、开心、害怕、还是别的？"
   - **对自己的看法**："在那个场景里，你觉得自己是个什么样的孩子？"
   - **对他人的看法**："你觉得其他人怎么样？他们是友善的、危险的、还是冷漠的？"
   - **对世界的看法**："从那个场景里，你觉得世界是什么样的？是安全的、危险的、还是需要努力争取的？"
   - **结局或应对**："后来怎么样了？你是怎么应对的？"

3. **识别重复主题**：
   - 在用户分享了1-3个记忆后，简要总结其中反复出现的主题
   - 使用暂定语言："我注意到这几个记忆里好像都有一个主题——你似乎总是在观察别人的反应，然后决定自己该怎么做。这贴近你的感受吗？"
   - 邀请用户修正或补充

**提问分寸**：
- 早期记忆是投射测试，不是事实核查——不要质疑记忆的准确性
- 记忆的内容不重要，重要的是用户对记忆的解读和感受
- 不把单一记忆当成生活风格的证据，需要结合家庭星座和当前功能综合判断
- 如果用户想不起早期记忆，不要强迫，可以说"没关系，想不起来也很正常，我们可以从其他方面开始"
- 一次只深入探索一个记忆，不要同时问多个

---

### 阶段4：当前功能探索（10-15分钟）

**目标**：了解用户当前如何处理阿德勒的三大生活任务——工作/学习、友谊、亲密关系，这是生活风格在当前生活中的体现。

**探索维度**（按需选择）：

1. **工作/学习**：
   - "你现在的工作/学习状态怎么样？"
   - "面对挑战或压力的时候，你一般会怎么应对？"
   - "和权威（领导、老师）相处的时候，你一般是什么模式？"
   - "你对成就和成功的看法是什么？"

2. **友谊**：
   - "你和朋友的关系怎么样？一般怎么建立和维持友谊？"
   - "和朋友有冲突的时候，你一般怎么处理？"
   - "你觉得自己在朋友中是什么样的角色？"
   - "你对信任和亲密的看法是什么？"

3. **亲密关系**（如果用户愿意聊）：
   - "你对亲密关系的看法是什么？"
   - "在亲密关系中，你一般是什么模式？"
   - "有没有什么反复出现的关系模式？"
   - 注意：如果用户没有亲密关系或不想聊，尊重其选择，不要强迫

**提问分寸**：
- 三大生活任务是阿德勒的框架，但不要用术语，用自然的语言提问
- 一次只问一个问题，根据用户的回答自然延伸
- 如果用户在某个领域有困扰，可以稍微深入，但不要变成问题解决
- 目标是理解模式，不是解决具体问题
- 区分"当前状态"和"长期模式"——当前状态可能受情境影响，长期模式更能反映生活风格

---

### 阶段5：整合与反馈（10-15分钟）

**目标**：基于前面的探索，进行阿德勒式个案概念化，生成初步的生活风格画像，呈现给用户，邀请修改和补充。

**重要原则**：
- 画像是**暂定的工作假设**，不是定论或诊断
- 所有维度都是通过间接方法推断的，不是直接问用户的
- 用自然语言呈现，不用术语
- 用户的修改和校正优先于系统的推断

**步骤**：

1. **个案概念化（内部处理，不直接展示给用户）**：

   基于前面三个阶段收集的材料（家庭星座、早期记忆、当前功能），进行阿德勒式个案概念化，推断9个核心维度。这是Skill的内部思考过程，不需要展示给用户。

   **维度推断指南**：

   | 维度 | 从家庭星座推断 | 从早期记忆推断 | 从当前功能推断 |
   |------|--------------|--------------|--------------|
   | **自我概念** | 在家庭中的位置和角色（被期待的/被忽视的/照顾者/调皮的） | 在记忆中是什么角色（主动的/被动的/观察者/受害者/拯救者） | 如何描述自己在工作/友谊/亲密关系中的表现 |
   | **理想自我** | 在家庭中渴望获得什么（关注/认可/自由/安全/爱） | 在记忆中渴望成为什么/渴望获得什么 | 对成功和成就的看法、羡慕什么样的人 |
   | **世界观** | 家庭氛围（温暖的/紧张的/冷漠的/控制的） | 世界在记忆中是安全的还是危险的、可预测的还是混乱的 | 如何描述当前的生活环境、对未来的看法（乐观/悲观） |
   | **他人观** | 父母和兄弟姐妹是什么样的（这是对"他人"的最初体验） | 他人在记忆中是什么形象（友善的/危险的/冷漠的/评判的/不可靠的） | 如何描述朋友、同事、伴侣、对他人的基本信任程度 |
   | **私人逻辑** | 在家庭中形成的规则（"如果我听话，妈妈就会爱我"） | 从记忆中推断的"如果...那么..."逻辑 | 在不同情境中反复出现的思维模式、用户的"应该"陈述 |
   | **基本错误** | 从家庭经历中推断的核心信念偏差 | 从记忆中推断的扭曲认知 | 从当前功能中推断的思维模式偏差 |
   | **行为策略** | 在家庭中用什么方式获得关注/爱/安全（讨好/表现/生病/叛逆/退缩） | 在记忆中如何应对（逃避/对抗/讨好/独立解决/寻求帮助） | 在工作/友谊/亲密关系中如何应对压力和挑战、面对冲突/失败/压力时的典型反应 |
   | **社会兴趣** | 在家庭中的角色和贡献（照顾者/被照顾者/旁观者/合作者） | 在记忆中是否关心他人、是否有合作、是否有归属感 | 对工作的看法（只是赚钱/有意义的贡献）、如何建立和维持友谊、在亲密关系中的模式 |
   | **自卑感与补偿方式** | 在家庭中是否感到被忽视/被比较/被要求、是否有兄弟姐妹的比较 | 在记忆中是否感到不足、如何应对 | 在哪些领域感到不足、如何应对这些不足（努力提升/逃避/攻击他人/自我贬低） |

   **置信度判断**：
   - 高：多个来源（家庭星座+早期记忆+当前功能）一致
   - 中：单个来源或部分一致
   - 低：推测或材料不足
   - 材料不足的维度标注为"待探索"

2. **生成生活风格概览**：

   基于个案概念化的结果，用自然语言生成2-3句话的核心摘要，概括用户的核心生活风格。这是用户首先看到的部分，应该简洁、有洞察力、用暂定语言。

   示例："你似乎是一个通过努力证明自己来获得安全感的人，对他人的评价比较敏感，在压力下倾向于独立解决问题而不是求助。"

3. **生成初步画像**：

   使用 `templates/lifestyle-profile.md` 模板，基于个案概念化的结果，填写9个核心维度：
   - 自我概念（Self-Concept）：我是谁
   - 理想自我（Self-Ideal）：我想成为谁
   - 世界观（World View）：世界是什么样的
   - 他人观（View of Others）：他人是什么样的
   - 私人逻辑（Private Logic）：生活中遵循的潜规则
   - 基本错误（Basic Mistakes）：核心信念中的错误模式
   - 行为策略（Behavioral Strategies）：常用的应对方式（含短期获得和长期代价）
   - 社会兴趣（Social Interest）：归属感、贡献感、信任感、合作能力
   - 自卑感与补偿方式：建设性补偿 vs 破坏性补偿

   每个维度标注：
   - 置信度：高 / 中 / 低
   - 来源：家庭星座 / 早期记忆 / 当前功能 / 多个来源
   - 用户校正空间

4. **呈现给用户**：
   - 先呈现生活风格概览（2-3句话）
   - 然后呈现各个维度的详细内容
   - 用自然的语言呈现，不要像报告或诊断
   - 强调这是"暂定的理解"，不是定论
   - 例如："基于我们刚才的聊天，我对你的生活风格有了一些初步的理解。我先说，你来看看哪些贴近，哪些不对。"

5. **邀请修改和补充**：
   - "你觉得哪些地方说得对？哪些地方不对或者不完整？"
   - "有没有什么你觉得很重要，但我没有提到的？"
   - "你可以直接修改任何一条，或者告诉我你想怎么改。"
   - 用户的修改和校正优先于系统的推断

6. **说明画像的价值和后续使用**：
   - "这个画像会帮助我们在后续的探索中，更快地看到你行为背后的模式和目的，提供更个性化的阿德勒式分析。"
   - "它不是对你的定义，而是我们共同理解你的一个起点。"
   - "你可以随时查看、修改、删除任何内容，或者要求重新评估。"
   - "如果你不想保存，也可以只作为这次对话的总结，不存入档案。"

7. **询问是否保存**：
   - 如果用户启用了持久化档案，询问是否将画像保存到档案
   - 如果用户未启用持久化档案，画像仅作为本次对话的总结，不持久化保存

8. **保存流程（用户确认保存后执行）**：

   **重要：必须实际执行保存脚本，不能只是说"保存成功"**

   **8.1 保存前的准备**：
   - 确认用户已启用持久化档案
   - 如果用户使用加密存储，先按照加密存储密码使用规则确认密码
   - **严禁在思考过程中暴露密码**：密码只能通过环境变量传递给保存脚本，不能在思考过程中提及或对比
   - **安全要求**：密码必须通过环境变量 `ADLERIAN_PASSWORD` 传递，**严禁在命令行参数中明文传递密码**（命令行参数中的密码会暴露在进程列表、终端历史和日志中）

   **8.2 构建画像数据 JSON 文件**：
   - 将本次初步画像的所有内容整理成 JSON 格式，写入一个临时文件（如 `outputs/profile_to_save.json`）
   - JSON 格式必须包含以下字段：
     - `current_focus`：用户当前关注的议题和回应偏好
     - `confirmed_understandings`：本次初步画像中用户确认的核心理解列表
     - `pending_understandings`：待验证的理解列表
     - `trigger_boundaries`：敏感话题和回应偏好
     - `strengths_and_values`：用户优势和价值观
     - `confirmed_patterns`：已确认的重复模式列表
     - `lifestyle_overview`：生活风格概览，包含：
       - `core_summary`：核心摘要（2-3句话概括用户的核心生活风格）
       - `key_themes`：当前最突出的主题（列表）
       - `confidence`：置信度（高/中/低）
       - `note`：说明（画像是暂定的工作假设，不是定论）
     - `core_dimensions`：核心维度（9个阿德勒心理学维度），每个维度包含：
       - `self_concept`：自我概念（我是谁）
       - `self_ideal`：理想自我（我想成为谁）
       - `world_view`：世界观（世界是什么样的）
       - `view_of_others`：他人观（他人是什么样的）
       - `private_logic`：私人逻辑（生活中遵循的潜规则）
       - `basic_mistakes`：基本错误（核心信念中的错误模式）
       - `behavioral_strategies`：行为策略（常用的应对方式）
       - `social_interest`：社会兴趣（对他人和共同体的关心程度）
       - `inferiority_and_compensation`：自卑感与补偿方式
       - 每个维度包含：`core_belief`（核心认知）、`details`（详细说明，列表）、`source`（来源）、`confidence`（置信度）、`user_correction`（用户校正）
   - 每个已确认理解必须包含：`id`、`title`、`user_expression`、`shared_summary`、`applicable_contexts`、`evidence_and_confirmation`、`confirmed_at`、`related_dimension`（关联的核心维度）

   **8.3 调用保存脚本（主路径：画像 + 完整对话一次性串联保存）**：

   保存画像时，**必须同时保存本次画像建立的完整对话原文**。为避免"先存画像、再单独存对话"两步脱节出错，统一用 `save_profile.py` 的 `--transcript-input` 参数，在一次调用内先校验保存完整对话、再保存画像：
   - 未加密存储：
     ```
     python scripts/save_profile.py --input <画像JSON> --transcript-input <对话JSON> --storage-mode local_unencrypted
     ```
   - 加密存储（密码通过环境变量传递，**严禁在命令行中明文传递密码**）：
     ```
     $env:ADLERIAN_PASSWORD="<密码>"; python scripts/save_profile.py --input <画像JSON> --transcript-input <对话JSON> --storage-mode local_encrypted
     ```
     执行后 `Remove-Item Env:ADLERIAN_PASSWORD` 清除环境变量。
   - 参数说明：
     - `--input`：上一步构建的画像 JSON 文件路径
     - `--transcript-input`：按 8.3.1 准备好的完整对话 JSON 路径；对话校验不过会整体中止，画像也不会写入
     - `--storage-mode`：`local_unencrypted`（默认）或 `local_encrypted`
   - 仅当本次确实没有可保存的对话原文（见 8.3.1"拉不到时"）时，才允许只用 `--input` 保存画像，并在反馈中如实告诉用户本次只存了画像、没存逐字对话。
   - **安全要求**：密码只能走环境变量 `ADLERIAN_PASSWORD`，严禁 `--password` 明文参数、严禁在回复或思考中出现密码；执行后清除环境变量。
   - **【路径铁律】所有规定脚本都使用基于脚本自身位置的绝对路径，数据固定落到本 Skill 目录下的 `storage/data/default/`，与你运行命令时所在的工作目录无关**：
     - 严禁自己临时编写保存脚本，必须直接复用 `scripts/` 下已规定的脚本
     - 严禁把数据写到聊天窗口工作目录或其他任意目录
     - 保存是否成功以脚本输出为准，不要反复 ls/dir 排查、不要在思考过程中描述这些动作

   **8.3.1 完整对话记录只能来自"会话历史读取工具拉取的真实原文"（最高优先级，反复出错后的最终结论）**

   完整对话记录用于后续深度分析和用户回看原始上下文，必须是本次画像建立过程中**每一轮 user/assistant 消息的真实原文**。

   **🛑 最关键的一条：严禁凭你的记忆/上下文"复述、还原、扩写"对话，更严禁根据画像摘要反推对话。**
   模型从记忆里重建长对话，必然概括、压缩，甚至编造出用户根本没说过的话；即使凑成"一来一回、数量对等"的样子，内容仍是假的（曾出现按画像编出"靠日语逆袭"这种用户没说过的内容）。**唯一可靠的来源，是调用平台的会话历史读取能力，把真实消息拉下来，原样写入。**

   **第一步：调用会话历史读取工具，拉取本次对话的真实消息（必做）**
   - 豆包环境：调用会话历史读取工具（`im_get_conversation_messages`），传入**当前会话 ID**，用 `turn_limit` / 分页游标（`next_cursor`、`has_more`）**从最早一轮分页拉到当前**，直到 `has_more=false`，确保覆盖从"开启画像"到"确认保存"的全部轮次，不遗漏。
   - 平台中立原则：换到其他运行平台时，替换为该平台等价的"读取本会话历史消息"能力，原则不变——**必须是工具返回的真实消息，不是模型回忆**。
   - 从工具返回中，对每条消息取三样东西，原样保留：`role`（user/assistant）、`content[].text`（**逐字原文，一个字不改**）、`created_at`（该消息的**真实时间**，作为 timestamp）。

   **第二步：原样组装对话 JSON（临时放 outputs/，保存后删除）**
   - messages 严格按工具返回的时间顺序排列；用户发了几条就是几条 user，你回了几条就是几条 assistant，**不增、不减、不合、不改写**。
   - 每条都带工具返回的真实 `timestamp`（脚本不再自动补当前时间——全部时间戳相同正是"凭记忆编造"的铁证，会被拒绝）。
   - 顶层必须带 `transcript_source` 来源凭证，声明这些消息确实来自会话历史工具：
   ```json
   {
     "summary": "初步画像建立：家庭星座、早期记忆、当前功能",
     "conversation_type": "initial_profile_building",
     "transcript_source": {
       "method": "conversation_history",
       "conversation_id": "当前会话ID",
       "turns": 21
     },
     "messages": [
       {"role": "user", "content": "工具返回的该条用户消息原文", "timestamp": "工具返回的created_at"},
       {"role": "assistant", "content": "工具返回的该条Skill回复原文", "timestamp": "工具返回的created_at"}
     ]
   }
   ```

   **第三步：用 8.3 的 `--transcript-input` 一次性串联保存**，脚本内置五道硬校验：
   1. **角色对等**：user/assistant 数量差≤2（防止只存用户归纳、丢 Skill 回复）；
   2. **交替性**：禁止连续 3 条同角色（防止多轮堆叠合并）；
   3. **反提纲**：超半数用户消息以"短标签："开头即判为归纳，拒绝；
   4. **真实时间戳**：每条必须带真实 created_at、可解析、按序递增；全部相同或长对话跨度异常短，判为批量伪造，拒绝；
   5. **来源凭证**：`transcript_source.method` 必须是 `conversation_history`；凭记忆/画像重构（model_recall 等）一律拒绝。
   - 被任一校验拒绝，说明你没有真正用工具拉原文（或在改写），**回到第一步重新用工具拉取**，严禁改脚本、删校验、自写脚本蒙混。
   - 看到成功输出并显示 user/assistant 条数才算成功；退出码非 0 就是失败，严禁对用户谎称已保存。

   **超长对话分段**：轮次太多时，先用第一段（含 transcript_source）创建，再用 `save_conversation.py --input <下一段> --append-to <对话ID>` 追加；每段消息同样带真实 timestamp，追加时对"已存+本段"整体重新校验。

   **拉不到真实历史时怎么办（重要，诚实优先）**：
   - **同一会话内**：历史工具一定能拉到，必须按上面做。
   - **跨会话**（画像对话在 A 会话、用户到 B 会话让你保存）：B 的历史工具读不到 A。此时只能请用户**引用/转发 A 会话**（如贴 conversation 链接）或提供原文；在用户提供之前，**如实告诉用户"那段对话不在当前会话，我无法读取原始记录，这次只能先保存画像摘要，不能编造逐字对话"**。
   - **绝对不允许**：为了凑满"对等格式"或让校验通过，而根据画像/记忆编造、补全、想象任何一条消息。宁可如实说存不了完整原文，也不存假对话。

   **严禁的行为**：
   - ❌ 严禁凭记忆/上下文复述、还原、扩写对话，严禁按画像摘要反推对话
   - ❌ 严禁只存用户消息、丢掉 Skill 回复，或把原话压成摘要/要点/"标签：内容"提纲
   - ❌ 严禁给消息统一补保存时刻的时间戳、伪造 created_at
   - ❌ 严禁省略或伪造 transcript_source 来源凭证
   - ❌ 严禁校验失败后改脚本/删校验/自写脚本蒙混，必须回到工具重新拉取
   - **加密存储时**完整对话通过同一加密适配器自动加密
   - **严禁暴露内部技术操作细节**：不对用户说"我调用了某工具/脚本""校验未通过"，用自然语言告知结果；拉不到时如实说明，绝不假装成功

   **8.4 解析保存脚本的输出**：
   - 保存脚本执行成功时，会输出"画像保存成功"以及保存内容摘要
   - 保存脚本执行失败时，会输出错误信息并返回非零退出码
   - **必须检查保存脚本的退出码和输出**：
     - 如果退出码为0且输出包含"画像保存成功"，说明保存成功
     - 如果退出码非0或输出包含"错误"，说明保存失败，**必须明确告知用户保存失败**，不要假装保存成功
   - 如果保存失败，可以重试一次；如果重试仍然失败，告知用户当前保存功能有问题，建议稍后再试

   **8.5 保存后的反馈**：
   - 根据保存脚本的输出，告诉用户保存成功
   - 简要说明保存了哪些内容（比如"保存了5条已确认的理解、2条待验证的理解、3个重复模式"）
   - **说明完整对话记录也已保存**："同时保存了本次对话的完整记录，用于后续深度分析和你查看原始上下文。你可以随时说'查看完整对话记录'来查看。"
   - **自动合并之前的零散洞察（重要）**：如果用户在建立初步画像之前已经进行过探索性对话并保存了洞察（画像状态为 `partial`），`save_profile.py` 会自动将这些已确认的洞察重新累积到新建立的完整画像中，不会丢失。保存后应该告诉用户："你之前保存的 X 条零散理解已自动合并到这份完整画像中，不会丢失。"
   - 说明用户可以随时说“查看画像”来查看保存的画像（生成 `我的生活风格画像.md`），说“查看档案”来查看完整对话原文（生成 `我的对话档案.html`），两者分开
   - 说明用户可以随时要求修改、删除或重新评估画像
   - **严禁暴露内部技术操作细节**：不要说"我调用了save_profile.py脚本"、"我写入了profile.json文件"、"我设置了环境变量"等技术细节，直接用自然语言告诉用户保存结果
   - **严禁在思考过程或回复中暴露密码**：密码只能通过环境变量传递给保存脚本，不能在任何地方提及
   - **安全操作**：执行完保存脚本后，应清除环境变量中的密码，避免密码残留在环境中

   **8.6 导出为 Markdown 格式（可选）**：

   保存画像后，可以询问用户是否需要导出为 Markdown 格式的完整报告：

   - **询问用户**："你需要我把这份画像导出为一个完整的 Markdown 文件吗？这样你可以随时打开查看，也可以转换为 Word/PDF 格式保存。"
   - **如果用户同意**：执行导出脚本 `python scripts/export_profile_to_markdown.py`，生成完整的 Markdown 报告
   - **如果用户不同意**：不导出，画像保存在档案中，用户可以随时说"导出画像"来导出
   - **导出后的反馈**：告诉用户导出成功，说明报告包含的内容，告诉用户文件的位置（用友好的方式说明）
   - **严禁暴露内部技术操作细节**：不要说"我调用了export_profile_to_markdown.py脚本"等技术细节

**输出**：
- 初步的生活风格画像（使用 `templates/lifestyle-profile.md`）
- 每个维度标注置信度和来源
- 用户修改后的版本优先
- 保存成功后的确认信息（基于保存脚本的实际输出）

## 提问分寸（通用原则）

- **以自然对话替代固定题序**：每一轮都从用户刚刚表达的内容出发，不要机械地按顺序提问
- **一次只问一个问题**：严禁同时问两个或多个独立问题，即使用"或者""还是""以及"连接也不行
- **用户可以跳过任何话题**：家庭、早期记忆、亲密关系等敏感话题始终可跳过，不能作为完成画像的条件
- **不把单一材料当成定论**：出生顺序、家庭事实、单一记忆、单一事件都不是生活风格的证据，需要综合判断
- **使用暂定语言**：提出理解时必须使用"也许""可能""我有一个猜测""不一定对"等暂定语言，禁止直接断言
- **区分事实和主观解读**：阿德勒心理学中，用户的主观解读比客观事实更重要。不要质疑用户的记忆或感受的"真实性"
- **关注用户的控制权**：始终让用户感受到自己有选择权、控制权，可以随时暂停、跳过、修改或结束
- **不急于生成画像**：如果材料不足，可以只生成部分画像，缺失的维度标注为"待探索"，不要为了"完整"而编造

## 与其他工作流的关系

| 工作流 | 关系 |
|--------|------|
| `first-use.md`（首次使用引导） | 在首次使用引导中，询问用户是否希望进行初步画像建立 |
| `initial-assessment.md`（初步探索工作流） | 初步画像建立是更全面的整体评估；初步探索是围绕单个问题的深入探索。用户可以选择其中一个，也可以都做 |
| `daily-dialogue.md`（日常对话与档案更新） | 初步画像建立完成后，后续对话进入日常对话与档案更新，持续更新和修正画像 |
| `profile-driven-dialogue.md`（画像驱动对话） | 初步画像建立完成后，画像驱动对话可以基于画像提供个性化回应 |
| `pattern-recognition.md`（跨时间模式识别） | 初步画像为模式识别提供背景，但模式识别仍需基于至少3个独立实例 |
| `pattern-review.md`（定期校准回顾） | 定期回顾时可以重新评估和更新画像 |

## 异常与分支

| 情形 | 处理 |
| --- | --- |
| 用户觉得问题太多或不想继续 | 立即减少问题，提供暂停、换议题或结束。可以基于已有材料生成部分画像，缺失维度标注"待探索" |
| 用户不同意画像中的理解 | 承认并修正，不把该理解保留为既定推断。用户修改后的表达优先 |
| 用户只给抽象描述 | 可邀请一个具体例子；若不愿提供，继续基于已有内容，不强迫具体化 |
| 用户希望直接得到结论 | 说明可先提供一个暂定看法，并请其校正；不宣称看透用户 |
| 议题涉及高风险或创伤 | 先安全和陪伴；不将其作为完成初步画像的材料。必要时转入即时危险回应 |
| 用户想不起早期记忆 | 没关系，想不起来也很正常，可以从家庭星座或当前功能开始。不要强迫 |
| 用户不想聊家庭或亲密关系 | 尊重其选择，跳过该话题，基于其他维度生成画像。不要追问或暗示"逃避" |
| 用户在探索中情绪激动 | 先共情和陪伴，不急于继续提问或生成画像。情绪稳定后再确认是否继续 |
| 用户要求跳过初步画像建立 | 尊重其选择，转入初步探索工作流。不要劝说或暗示"不做就不完整" |
| 用户启用了加密存储 | 在保存画像前，按照加密存储密码使用规则，要求用户输入密码（如需要）。**严禁在思考过程中暴露密码**：严禁在思考过程中提及、对比、或暴露用户密码。密码验证必须通过调用存储适配器的 `verify_password` 方法来完成，不能在思考过程中对比密码。思考过程中只能说"密码验证中"或"密码验证成功/失败"，不能提及具体密码。 |
