# 画像驱动对话工作流

> ✅ **已实现，可选启用**：本工作流依赖持久化档案与生活风格画像功能，本地存储适配器已实现（`storage/adapters/local_json.py` 未加密、`local_encrypted.py` 整体加密，支持两种模式，默认未加密）。默认不启用，需要用户明确选择后才生效。启用后基于生活风格画像提供个性化回应。

## 目标与完成条件

本工作流把生活风格画像用作持续协作的背景，而不是对用户的定义。它负责决定当次材料能停留在哪一级、何时可以帮助个性化回应、何时必须等待更多证据，以及用户修正或删除后如何回退。

完成条件是：本轮回应只使用与当前目标相关、且状态和授权允许的材料；任何新增理解都已明确其等级、依据和用户可选操作。没有足够材料时，保持在当次探索，不为填满画像而升级。

## 进入条件

当用户在不存在即时危险时进行初步探索、深入探索、档案更新、主动查看画像、跨时间对照或模式识别时使用。需要读取跨会话材料时，先遵守 `storage/memory-retrieval-spec.md` 的最小证据包；未开启档案、全量锁定、即时危险或平台能力未验证时，只基于当前对话回应，不形成或引用跨会话画像。

未获探索授权时不进入本工作流的跨会话升级路径。

**用户明确要求基于画像分析时的强制触发**：当用户明确要求"基于我的画像分析"、"根据我的画像"、"参考我的档案"、"结合我的画像"、"从我的画像角度"等表述时，**必须首先读取已保存的画像**，然后基于画像内容进行分析。具体要求：

### 读取画像的具体步骤（必须严格执行）

1. **确认存储模式**：
   - 如果用户启用了加密存储（`local_encrypted`），先要求用户输入密码（见下方"加密存储的密码确认"章节）
   - 如果用户使用未加密存储（`local_unencrypted`），直接进入下一步

2. **初始化存储适配器**：
   - 未加密存储：`from storage.adapters.local_json import LocalJsonStorageAdapter`，然后 `storage = LocalJsonStorageAdapter(base_dir="storage/data", user_id="default")`
   - 加密存储：`from storage.adapters.local_encrypted import LocalEncryptedStorageAdapter`，然后 `storage = LocalEncryptedStorageAdapter(base_dir="storage/data", user_id="default", password=用户输入的密码)`

3. **读取画像文件**：
   - 调用 `profile = storage.read_profile(lite=False)` 读取全量版画像
   - 画像文件位置：`storage/data/default/profile.json`（全量版）或 `profile.lite.json`（精简版）

4. **检查画像是否为空**：
   - 检查 `profile.get("confirmed_understandings", [])` 是否有内容
   - 如果为空（没有已确认的理解），说明用户还没有保存的画像
   - **严禁用对话历史里的信息拼凑画像**，不能用之前对话中提到的内容代替已保存的画像

5. **基于画像内容进行分析**：
   - 如果画像非空，基于画像中的 `confirmed_understandings`、`confirmed_patterns`、`strengths_and_values` 等内容进行分析
   - 如果使用了画像中的内容，应该简短说明关联（如"基于你画像中记录的..."），让用户知道分析是基于已保存的画像
   - 如果画像为空，告知用户"你还没有保存的画像，我们可以先建立一份初步画像"，不能假装读取了画像

### 其他要求

1. **必须读取档案中已保存的画像**，不能用对话历史里的信息拼凑画像，不能用之前对话中提到的内容代替已保存的画像
2. **如果档案中没有已保存的画像**，应该告知用户"你还没有保存的画像，我们可以先建立一份初步画像"，不能假装读取了画像
3. **读取画像后，如果使用了画像中的内容**，应该简短说明关联（如"基于你画像中记录的..."），让用户知道分析是基于已保存的画像
4. **如果用户启用了加密存储**，在读取画像前必须先确认密码（见下方"加密存储的密码确认"章节）
5. **严禁在思考过程中暴露密码**：读取加密画像时，密码验证必须通过调用存储适配器的方法完成，不能在思考过程中对比或暴露密码
6. **严禁暴露内部技术操作细节**：不要在回复中展示文件路径、目录结构、Python 代码、命令行输出等技术细节，直接以用户可见的方式回应

### 加密存储的密码确认（重要）

如果用户启用了加密存储，在进行任何需要读取生活风格画像的操作前（包括画像驱动对话、个性化回应、跨时间对照等），必须先确认密码：

1. **新对话会话必须重新输入密码**：每次开启一个新的对话会话时，第一次需要读取加密档案前，必须要求用户输入密码。密码不会跨会话持久化保存。

2. **同一次对话中的密码记忆选择**：用户第一次输入密码后，询问用户"是否在本次对话中记住密码？"：
   - 如果用户选择"记住"：本次对话中后续的档案读写操作不需要再次输入密码
   - 如果用户选择"不记住"：每次档案读写操作前都需要重新输入密码
   - 对话结束后，密码自动失效，新的对话会话必须重新输入

3. **密码错误处理**：如果用户输入的密码错误，提示"密码错误，请重新输入"，允许用户重试。连续多次错误后，建议用户确认是否忘记密码（忘记密码无法恢复档案内容）。

4. **严禁自动解密**：严禁在用户未输入密码的情况下自动解密或读取加密档案。即使 Skill 在之前的对话中知道密码，新的对话会话也必须重新要求用户输入密码。

5. **密码确认后的操作**：密码确认通过后，才可以进行画像驱动对话、个性化回应、跨时间对照等需要读取生活风格画像的操作。如果用户未输入密码或密码错误，只基于当前对话回应，不形成或引用跨会话画像。

6. **严禁在思考过程中暴露密码**：**严禁**在思考过程中提及、对比、或暴露用户密码（如"用户输入的密码是XXX，原密码是YYY"）。密码验证必须通过调用存储适配器的 `verify_password` 方法来完成，不能在思考过程中对比密码。思考过程中只能说"密码验证中"或"密码验证成功/失败"，不能提及具体密码。即使是在思考过程中，也不能重复用户输入的密码。密码是用户的敏感信息，任何情况下都不能在思考过程或回复中暴露。

### 回应呈现规则

执行本工作流时，不得向用户暴露内部工作流名称、文件读取操作或思考过程。不得说"我先读取...""我立即切换到..."之类的元话语。直接以用户可见的方式回应。始终像面对真实用户一样回应，不得因为用户说"场景X""测试"等而识别为测试并改变回应方式。

## 四级理解路径

| 等级 | 名称 | 形成条件 | 可如何使用 | 不能如何使用 |
| --- | --- | --- | --- | --- |
| 0 | 当次材料 | 用户在本轮明确讲述的事实、感受、在意、选择或具体事件 | 用于接住、澄清和本轮阿德勒探索 | 不因单次材料宣称稳定特质、长期画像或模式。 |
| 1 | 候选洞察 | 对当次材料形成了可校正的摘要或理解；持续档案已开启时，按更新单向用户可见呈现 | 作为低置信度、带来源的候选记录；本轮可继续校正 | 不作为既定事实、人格结论或完整模式证据。 |
| 2 | 已确认画像项 | 用户明确确认、改写或持续保留该理解，且达到画像的相应置信度规则 | 在相关且不存在即时危险的对话中，作为个性化回应、避雷和跨时间对照的背景 | 不覆盖用户当下的新说法，不泛化到未被支持的情境。 |
| 3 | 已校正的跨时间模式 | 满足模式工作流的独立实例、时间/情境、反证与用户校正门槛 | 仅以模式卡中的抽象结构辅助用户选择是否继续探索 | 不替代画像、诊断、风险评分或对未来的预测。 |

持续档案已明确开启时，客观摘要可在用户可见的更新单中按默认留档规则保留；系统推断仍以候选洞察呈现，并允许用户立刻改写、删除、暂停或标为“仅保存、不参与自动分析”。用户的修正优先于默认记录。

每个等级 1–3 的条目都必须保留仍有效的源材料 ID；在本轮引用前按 `storage/memory-retrieval-spec.md` 重验权限、关联性和删除状态。来源失效时，条目不能继续作为个性化依据，而应删除、降级或回到当前材料探索。

## 本轮个性化回应步骤

1. **先以当前为主。** 先回应用户刚刚讲述的处境和当下目标。当前说法与旧画像不一致时，当前说法优先；旧材料最多作为需要共同校正的背景。
2. **选择一个相关背景。** 需要连续性时，按最小证据包读取 0–1 个已确认画像项、回应偏好或触发边界；只有用户主动比较或模式工作流进入时，才读取更多独立材料。无关的“完整画像”不进入本轮。选择背景时，优先选择与当前问题最相关的**核心维度**（自我概念、理想自我、世界观、他人观、私人逻辑、基本错误、行为策略、社会兴趣、自卑感与补偿方式），而不是随意选择一个画像项。
3. **基于画像进行个案概念化（内部处理，不直接展示给用户）。** 基于选择的核心维度，回答以下个案概念化的核心问题，形成对这个用户的深入理解：
   - **共同主题**：当前问题与画像中的核心维度有什么共同主题？是什么把这些问题连接起来？
   - **形成根源**：现在这套模式是怎么在早年经历（家庭星座、早期记忆）里形成的？
   - **维持因素**：是什么在维持这个模式？（短期获得、私人逻辑、基本错误）
   - **保护功能**：这个模式在保护用户什么？（避免什么痛苦、守住什么价值）
   - **资源和力量**：用户有哪些力量和资源可以用来改变？
   这是Skill的内部思考过程，不需要展示给用户，但会影响后续的分析角度和提问。
4. **形成个性化的分析角度和提问。** 基于个案概念化的结果，形成针对这个用户的个性化分析角度和提问，而不是泛泛的理论套用：
   - **个性化分析角度**：不是简单说“这是目的论”，而是说“你这次的回避，可能和你画像中记录的‘通过独立来保护自己’有关——你回避的背后，可能是在保护自己不被伤害”。
   - **个性化提问**：基于用户的核心维度，提出有深度的问题（具体示例见下方“基于核心维度的个性化分析指南”）。
   - **一次只问一个问题**：严禁同时问两个或多个独立问题。
5. **把理论落到这个人身上。** 不存在即时危险且用户愿意探索时，先对照 SKILL.md"阿德勒式回应方式"中的**概念调度决策表**，根据当前问题和画像选一个最相关的阿德勒概念（目的论不是默认角度），用直率话术提出理解；对具体用户的应用仍允许其校正，不把理论变成泛泛安慰或机械套话。分析时要基于前面形成的个性化分析角度，而不是泛泛的理论。
6. **说明连续性但不夸大。** 只有明确使用了历史材料时，才简短说明关联，例如“我参考了你先前确认过的、在评价压力大时更想先退一步这一点”。不要说“我比你更了解你”“你一直就是这样”或暗示读取了无关档案。
7. **决定本轮停留等级。** 只在当前材料足以帮助理解时生成候选洞察；是否进入画像或模式，按下节升级规则判断。用户可以选择只停在理解，不产生任何长期产物。

## 基于核心维度的个性化分析指南

> 本指南说明每个核心维度如何影响分析角度和提问，确保画像真的能改变分析的深度，而不只是简单引用。

### 自我概念（Self-Concept）

- **如何影响分析**：用户如何看待自己，会影响他对当前事件的解读。例如，如果用户的自我概念是“我是不够好的”，那么一次普通的批评可能会被解读为“我果然不行”。
- **个性化提问示例**：
  - “你觉得这次的事，是不是又让你觉得‘我不够好’？”
  - “如果换一个你觉得‘足够好’的人，他会怎么看待这件事？”
  - “你对自己的这个看法，是从什么时候开始的？”

### 理想自我（Self-Ideal）

- **如何影响分析**：用户希望成为什么样的人，会影响他对自己的要求和评价标准。例如，如果用户的理想自我是“我希望被所有人喜欢”，那么一次被拒绝可能会被解读为“我失败了”。
- **个性化提问示例**：
  - “你觉得这次的事，是不是没有达到你希望的‘完美’？”
  - “你希望成为的那个人，会怎么处理这件事？”
  - “如果不需要让所有人都满意，你会怎么做？”

### 世界观（World View）

- **如何影响分析**：用户如何看待世界，会影响他对事件的预期和反应。例如，如果用户的世界观是“世界是危险的”，那么一个新的机会可能会被解读为“有风险”。
- **个性化提问示例**：
  - “你觉得这次的事，是不是又让你觉得‘世界是不安全的’？”
  - “如果世界是安全的，你会怎么看待这件事？”
  - “你对世界的这个看法，是从什么时候开始的？”

### 他人观（View of Others）

- **如何影响分析**：用户如何看待他人，会影响他在人际关系中的行为和预期。例如，如果用户的他人观是“他人是评判者”，那么在权威面前会特别紧张。
- **个性化提问示例**：
  - “你觉得他/她这次的反应，是不是又在‘评判’你？”
  - “如果他人不是评判者，而是和你平等的人，你会怎么看待这件事？”
  - “你对他人的这个看法，是从什么时候开始的？”

### 私人逻辑（Private Logic）

- **如何影响分析**：用户生活中遵循的潜规则，会影响他的决策和行为。例如，如果用户的私人逻辑是“如果我示弱，就会被伤害”，那么他会倾向于回避冲突和求助。
- **个性化提问示例**：
  - “你觉得这次如果不这样做，会发生什么？是不是又在遵循‘如果...就...’的规则？”
  - “这个规则是从什么时候开始的？它曾经保护过你吗？”
  - “如果这个规则不是真的，你会怎么做？”

### 基本错误（Basic Mistakes）

- **如何影响分析**：核心信念中的错误模式，会影响用户对事件的解读和反应。例如，如果用户的基本错误是“过于概括化”，那么一次失败可能会被解读为“我总是失败”。
- **个性化提问示例**：
  - “你觉得这次的事，是不是又让你觉得‘我总是这样’？”
  - “有没有一次情况不一样？那时有什么条件不同？”
  - “如果只看这次具体的事，而不是‘总是’，你会怎么看待？”

### 行为策略（Behavioral Strategies）

- **如何影响分析**：用户常用的应对方式，会影响他在压力下的行为。例如，如果用户的行为策略是“回避”，那么在面对挑战时会倾向于拖延或逃避。
- **个性化提问示例**：
  - “你这次选择这样做，是不是又在用‘回避/讨好/对抗’的方式来保护自己？”
  - “这种方式短期给了你什么保护？长期又让你失去了什么？”
  - “如果换一种方式，你觉得会发生什么？”

### 社会兴趣（Social Interest）

- **如何影响分析**：用户对他人和共同体的关心程度，会影响他在人际关系中的行为和满意度。例如，如果用户的社会兴趣较低，那么他可能会感到孤独和孤立。
- **个性化提问示例**：
  - “你觉得在这件事里，你和他人的连接是什么？”
  - “如果能感受到更多的归属感，你会怎么看待这件事？”
  - “你有没有什么时候觉得自己是某个共同体的一部分？那时是什么感觉？”

### 自卑感与补偿方式

- **如何影响分析**：用户的自卑感来源和补偿方式，会影响他的行为和目标。例如，如果用户的自卑感来自“被比较”，补偿方式是“努力证明自己”，那么他会倾向于过度追求成就。
- **个性化提问示例**：
  - “你觉得这次的事，是不是又触发了你的自卑感？”
  - “你现在用的补偿方式（努力/回避/攻击），短期给了你什么？长期又让你付出了什么代价？”
  - “如果不需要用这种方式来补偿，你会怎么做？”

## 升级、修正与回退

### 从当次材料到候选洞察

当次出现与用户目标、回应偏好、已发生变化或明确想保留内容有关的材料时，使用 `templates/insight-card.md` 或 `templates/archive-update.md` 分开呈现用户明确材料与系统理解。用户未开启档案时，洞察只留在当前对话；已开启档案时按默认留档的透明更新单处理。

### 从候选洞察到已确认画像项

候选洞察在以下任一条件满足时，才可被写为画像中的“已确认理解”：用户明确确认或改写后保留；或同一理解在独立材料中再次出现并符合既有置信度规则，且用户没有否认或限定其适用范围。未达到时，继续保留为低置信度待验证理解，或只作当次记录。

画像项必须保留：用户明确表达、共同整理、适用情境与例外、依据与最后确认。画像中的力量、价值、回应偏好和触发边界与理论推断分开保存，不能被推断覆盖。

### 从画像项到跨时间模式

已确认画像项可以帮助检索候选证据，但不能自己构成模式。只有按 `workflows/pattern-recognition.md` 完成独立事件去重、时间/情境分散、反证检查和用户校正后，才可生成模式卡。两个独立信号仍只允许一次轻提示。

### 回退与删除

- 用户不同意候选洞察：停止将其作为推断依据；若已保存，按用户选择删除或改写。
- 用户限定“只在某些情境”：将画像项缩小到该条件，不把它作为普遍描述。
- 新材料与旧画像冲突：并列呈现情境差异，转回待验证；不要求用户在同一轮选出“真正的自己”。
- 删除源材料、洞察或模式证据：按存储规范级联删除或失效所有派生物；证据不足的画像项降级为待验证，证据不足的模式卡撤回。

## 输出边界

- **当次探索**：自然语言回应、暂定探索地图或单次洞察卡，均可不留档。
- **候选洞察**：使用更新单，最多 2–3 条，标明来源、置信度与用户可选操作。
- **生活风格画像**：只在用户主动查看、校正或需要连续协作时读取/展示相关部分，不自动展示整份档案。
- **模式卡**：只按既有完整模式门槛生成，每次最多 1–2 个。

不使用勇气等级、人格类型、固定标签、成长分数、预测性判断或“档案完整度”。用户暂停、修改、删除、不想看或改变主意，都不是失败、回避或不配合。

## 异常与分支

| 情形 | 处理 |
| --- | --- |
| 当前用户的表达与旧画像相反 | 当前表达优先；将旧画像标为情境待校正，不拿旧记录反驳用户。 |
| 只有一次强烈、敏感或戏剧性的叙述 | 接住当下，最多形成可撤回候选；不升级为画像或模式。 |
| 用户只想要直接阿德勒分析，不想看档案 | 不存在即时危险时直接分析；不展示、保存或读取无关画像。 |
| 用户询问“你为什么这样理解我” | 说明当前材料与已授权抽象背景的关联，不复述私密原文；不能说明时撤回该关联。 |
| 对话转为明确即时危险 | 停止画像、洞察、模式与更新操作，转入安全工作流。 |
| 用户要求“导出画像”“保存画像为文件”“查看完整画像” | 执行画像导出流程（见下方“画像与档案的查看、导出”），生成 Markdown 格式的完整画像报告。 |

## 画像与档案的查看、导出

本 Skill 严格区分两种查看：触发词不同、脚本不同、文件格式不同，**严禁混淆**（与 SKILL.md 核心原则第 7 条完全一致）。

### 两种查看模式对照

| 用户意图 | 触发词示例 | 必须运行的脚本 | 交付文件（固定名，每次覆盖上一次） | 文件内容 |
|---|---|---|---|---|
| **查看画像** | “查看画像”“我的画像”“生活风格画像”“看看我是什么样的人”“我是谁”“导出画像” | `python scripts/export_profile_to_markdown.py --mode profile` | `我的生活风格画像.md` | 画像主体 + 对话记录摘要索引，**不含完整对话原文** |
| **查看档案** | “查看档案”“查看完整对话”“我的对话记录”“聊天记录”“看看我们聊过什么”“查看对话原文”“查看对话” | `python scripts/export_archive_to_html.py` | `我的对话档案.html` | 交互式 HTML，每段对话折叠成一行标题，点击展开看逐字原文 |
| **模糊表述** | “看看我的资料”“我的东西” | 不猜测，简短询问想看画像还是对话档案 | — | — |

### 查看画像流程（.md）

1. 确认 `storage/data/default/profile.json` 存在；不存在则告知用户还没有保存的画像、可以先建立一份，不能假装查看。
2. 加密存储时，密码只走环境变量 `ADLERIAN_PASSWORD`，**严禁 `--password` 明文传参、严禁在思考过程或回复中暴露密码**，脚本执行后用 `Remove-Item Env:ADLERIAN_PASSWORD` 清除。
3. 运行 `export_profile_to_markdown.py --mode profile`（脚本基于自身位置用绝对路径，与运行时工作目录无关）；检查退出码，输出包含“导出完成”才算成功。
4. 用 present_files 把固定文件 `outputs/我的生活风格画像.md` 作为附件发给用户；对话里只简要说明包含哪些章节，不铺全文。

### 查看档案流程（.html）

1. 运行 `export_archive_to_html.py`（加密时同样只走环境变量密码）。
2. 脚本读取 `storage/data/default/conversations/` 下全部未删除对话，按时间正序（最早在上、最新在最下）生成交互式 HTML：每段对话默认折叠为一行标题（日期+主题+条数+来源状态），点击展开逐字原文，支持“全部展开/全部收起”和目录锚点跳转，用户/Skill 消息配色区分，已做 HTML 转义。
3. **为什么档案用 HTML 而不是 Markdown**：Markdown 的 `<details>` 折叠标签在豆包等平台渲染器中不生效，对话多了无法折叠；HTML 用 CSS+JavaScript 实现折叠交互，浏览器打开即可用。
4. 用 present_files 把固定文件 `outputs/我的对话档案.html` 作为附件发给用户。

### 严禁行为（两种模式通用）

- 严禁在对话中用 Markdown 语法铺完整画像或完整对话原文；
- 严禁先在对话里展示、等用户提醒“给我文件”后才生成；
- 严禁自己手动整理、编写内容代替导出脚本，严禁跳过脚本直接写文件，严禁临时写导出脚本；
- 严禁把画像内容和完整对话混进同一个文件（两种模式必须分开）；
- 严禁查看档案时调用 export_profile_to_markdown.py，严禁查看画像时调用 export_archive_to_html.py；
- 严禁只在对话里说“已生成文件”却不调用 present_files 实际发送；
- 严禁暴露脚本名、文件路径、命令行、技术报错等内部细节（见 SKILL.md 原则 6），只自然语言告知结果。

### 画像的性质

- 画像是暂定的工作假设，不是对用户的定义，随时可以修订；
- 用户拥有完全控制权，可随时查看、修改、删除任何内容；
- 画像 `.md` 只含对话摘要索引；完整逐字原文只在档案 `.html` 中，二者不互相替代。
