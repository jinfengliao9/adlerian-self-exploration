# 暂定验证与置信度规则

## 用途

本资料规定如何把探索中的材料整理为用户可校正的暂定理解。它衡量的是“当前材料对某项理解的支持程度”，不是对用户、人格或叙述真实性的评分。

## 每项理解的三层结构

整理时始终分开呈现：

1. **用户明确材料**：用户亲自讲述的事件、感受、选择或修正；
2. **暂定理解**：系统基于材料提出的可能联系，使用“可能、也许、目前看来、需要你校正”等语言；
3. **待了解之处**：情境差异、例外、反证，或用户尚不想回答的部分。

先复述第一层，再提出第二层，最后邀请用户校正。未经用户确认的推断不能写成事实。

## 证据与独立性

可作为支持材料的来源包括当前具体事件、不同时间的其他事件、用户确认、例外经验、早期记忆、家庭叙述、情境想象和价值比较。

“独立材料”必须来自不同事件、不同情境或不同时间点。同一件事的重复讲述、系统复述、同一次更新单的多个字段，均只算一份材料。早期记忆、情境想象和价值比较只能提供低权重探索线索，不能单独提升为高置信度。

## 置信度

| 置信度 | 可见条件 |
| --- | --- |
| 低 | 单一材料；用户尚未确认；或存在未澄清的矛盾。 |
| 中 | 两个独立材料相互支持；或用户明确确认其只在某个情境成立。 |
| 高 | 用户明确认可，且至少三个独立情境或材料支持，并无重要反证。 |

高置信度仍是可修改的共同理解，不是最终结论。系统不应为了升级置信度重复盘问用户或安排隐蔽的一致性测试。

## 校正、反证与时间

- 用户不同意、修正或要求删除时，以其新的表达为准；原推断停止作为既定依据。是否保留修正历史，遵循用户的档案选择与存储能力边界。
- 出现新的可信冲突材料时，优先记录情境差异、例外或待验证关系；不逼用户决定哪一种才“真实”。
- 时间过去本身不降低置信度。长期未重新讨论的理解只标注“近期未复核”。
- 用户不想回答、记忆模糊或改变说法，只表示材料有限或情境变化，不表示不诚实。

## 输出与写入边界

当次探索先使用 `templates/exploration-map.md` 呈现事实和暂定理解。只有用户已开启持续档案且平台可以兑现查看、编辑、删除与派生删除控制时，才可按 `workflows/daily-dialogue.md` 生成候选更新单。

未开启档案、加密档案未解锁、即时危险，或平台能力未验证时，理解只保留在当次会话；不得暗中写入、称为已保存，或作为跨时间模式证据。

## 与模式识别的关系

单次或低置信度理解不能称为跨时间模式。两个独立事件最多构成一次轻提示；完整模式还须满足 `workflows/pattern-recognition.md` 的三个实例、跨两个以上情境或时间点、无重要反证与用户可校正条件。
